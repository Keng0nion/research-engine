# RESEARCH-ENGINE-BENCHMARK

新引擎与旧系统（DuckDuckGo 单通道）的对照实测。数据文件：`benchmarks/results-old.jsonl`、`benchmarks/results-new.jsonl`、`benchmarks/RESULTS-comparison.md`（由 `benchmarks/compare.py` 生成，可复跑）。

## 一、方法与口径（先声明局限，再谈结论）

- **题目**：12 题覆盖任务书要求的 12 个门类（数学、生物、化学、物理、计算机、机器学习、AI 研究、时事、GitHub 项目发现、中文文献、跨学科、技术文档），题库见 `benchmarks/questions.json`。
- **预算对齐**：双方均为单轮、单查询、无扩展。基线为 duckduckgo MCP（limit 15）；引擎为自动路由供应商集每源 8 条 + 至多 2 次全文获取尝试。双方 API 支出均为 0（全部免费通道）。
- **基线通道说明（如实）**：基线数据经 duckduckgo MCP 采集（旧系统的实际工具）。脚本化 DDG HTML 端点复跑时被限流全部返回 0，故采用 MCP 采集；题 1 首次返回 0（限流），重试时查询词微调（已在数据文件注明）。
- **学术命中口径不同**：基线为 URL 启发式（域名白名单包含判断），引擎为来源平台分类（six 学术 provider 判定）。两者不可直接相减，只作方向性参考。
- **词法相关性**：标题（基线）或标题加摘要（引擎）中命中查询实词的比例，是廉价代理指标，不是人工相关性判断。
- **«引擎独有来源»**：受基线采集广度限制（最多 10 至 15 条）与引擎全量文档列表的基数差异影响，97% 是上界性质的下限指示，不能解读为「DDG 找不到这些资料」。

## 四、结论（拒绝「链接更多即更好」的修辞）

**明确的改进（有实测支撑）**：
1. 来源多样性：同题单查询下唯一来源从约 10 到约 28；学术论文进入结果池成为常态（基线在计算机、新闻、工具、文档四类为 0）。
2. 全文能力：71% 的抽样学术文档取得真实全文（此前完全不具备该能力），且访问受限者被如实分级而非静默丢失。
3. 可审计性与衍生能力：引文图、存在性核验、证据卡、冲突候选、报告骨架均为新增的结构化产物；基线只有扁平链接列表。

**没变好或变差的地方（如实）**：
1. 延迟显著上升（p50 13.4 秒对秒级），不适合逐字逐句的低价值查询；quick 模式与既有 duckduckgo MCP 应继续承担轻量场景。
2. 供应商级错误率 19.3%：Semantic Scholar 共享池限流是主因；不影响交付但需在会话中如实上报缺口。
3. 中文文献题（#10）引擎 16 篇对基线 10 篇、全文 0/2：CNKI 未安装（用户可选），中文全文能力当前弱于学术英文场景，这是已登记的差距。

**未测与不声称**：未做 LLM 评审式质量分（RACE 式打分需付费模型，超出免费原则）；未测多轮深研的增量收益；未对每源做精确率人工标注。以上留作后续（见 KNOWN-LIMITATIONS）。
